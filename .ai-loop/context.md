# Segregator — рабочая память ai-loop

Читается в начале каждой фазы. Лимит — две страницы.
Полное ТЗ живёт отдельным артефактом claude.ai («ТЗ Segregator»), не в репозитории.

## Что это за проект

Автономная бухгалтерская ИИ-система для Польши (JDG и Sp. z o.o.). Первый
работающий кусок — разбор Telegram-канала «бухгалтерия» в архив: дерево папок
по месяцам и категориям, SQLite с полнотекстовым поиском, XLSX-реестр для
бухгалтера. Пользователь один — владелец JDG, он же единственный, кому бот
отвечает.

## Правило номер один

Документы и всё, что из них извлечено, **не покидают эту машину**. Есть две
плоскости: L (локальный рантайм, видит настоящие фактуры, PESEL, суммы) и
C (Claude Code, видит только код, правила, схемы и синтетические фикстуры).

Claude Code никогда не читает `JDG/`, `archiwum/`, `blobs/`, `*.db`, `logs/`,
`.env`. Для отладки берётся синтетическая фикстура из `tests/fixtures/`.

Следствие для цикла: агент не может посмотреть на проблемный документ. Отладка
идёт по обезличенному описанию — тип, длина текста, какие поля нашлись, номер
ступени каскада.

## Железо (замерено)

Ryzen 5 3500U, Vega iGPU, **NVIDIA нет** → vLLM не используем. RAM 6.9 ГБ,
свободно меньше гигабайта. Диск C: 19 ГБ из 237. Модель — `gemma-3-4b-it-Q4_K_M.gguf`
(2.32 ГБ), локально. Локальная модель — дорогой ресурс: каскад устроен так,
чтобы до неё доходили единицы процентов документов.

Считает деньги детерминированный Python под тестами; модель классифицирует и
объясняет, но не считает.

## Решения, которые уже приняты

- Дерево строится **hardlink**, не копиями: вдвое меньше места и, главное,
  hardlink на NTFS не требует режима разработчика — а именно из-за симлинков
  ТЗ §02 загонял дерево в WSL2. Требование WSL2 снимается.
- `LLM_BACKEND=llama.cpp`, не Ollama — на машине с почти нулевым запасом RAM
  постоянный демон дороже разового процесса. Ни то, ни другое ещё не установлено.
- Внешних LLM-API нет и не будет. Валидатор конфига падает на не-loopback адресе.
