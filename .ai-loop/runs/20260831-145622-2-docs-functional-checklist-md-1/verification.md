## A1 — свежий клон собирает тестовое окружение одной командой

в клоне из коммита `a9d4530`. После коммита тестов проверка повторяется
в SHIP.

**Статус: verified, все пять.**

Про раздел 6 спеки («как это может пройти и всё равно быть неверным»):
опасение «тест проверяет только один из путей утечки» закрыто
`test_no_raise_on_the_document_path_interpolates_export_data`.

**Инвариант переписан после ревью.** Первая редакция была на регулярке
`raise\s+\w+\((.*?)\)\n` — `scope-reviewer` показал, что она пропускает
конкатенацию (`"плохо: " + relative`), `.format(href)`, `%`-формат,
многострочный `raise X(...) from exc` и `raise` без скобок, то есть ровно
те формы, которыми утечка и вернулась бы. Переписано на `ast`: обходится
всё поддерево аргументов `ast.Raise`, любая форма попадает.

Проверено фальсификацией 7 — конкатенация, которую регулярка пропускала:
```
E  AssertionError: assert 'tajna-faktura-kowalski' not in
   'Путь вложения ведёт за пределы: ../../../tajna-faktura-kowalski.pdf'
```
Плюс `test_the_invariant_actually_catches_every_leak_shape` проверяет сам
инвариант на шести формах утечки — без него предыдущий тест мог бы быть
зелёным просто потому, что не умеет видеть утечку, и выглядел бы
доказательством её отсутствия.

**Область инварианта сужена честно.** Раньше заявлялась как «весь `ingest/`»,
а `F-9.3` в чек-листе претендовал на весь репозиторий. Теперь: пакеты
конвейера (`ingest`, `extract`, `classify`, `route`, `serve`).
`cli.py`/`config.py`/`paths.py` **намеренно вне** — их дело показать оператору
его собственную конфигурацию по его же запросу (`segregator doctor`), а не
данные документа посреди разбора. Решение записано в докстринге теста и как
**D20** в чек-листе, чтобы это было решением, а не недосмотром.

## A3 — percent-encoded href резолвится, traversal остаётся отбит

### A3.1 — decode работает
Сломано: `decoded = unquote(relative)` → `decoded = relative`.
```

```
То есть тест ловит именно отсутствие декодирования, включая польскую
диакритику.

### A3.2 — порядок decode → resolve → проверка (главное)
Сломано: проверка выхода за корень перенесена **до** декодирования
(`candidate = (root / relative).resolve()`, decode только в `return`).
```

   tests/test_ingest_html_reader.py:184  (%2e%2e%2f)
E  Failed: DID NOT RAISE <class 'ExportPathError'>
   tests/test_ingest_html_reader.py:191  (%2e%2e%5c, windows-разделитель)
2 failed, 17 passed
```
Это ключевая фальсификация прогона: она доказывает, что тесты держат
**порядок операций**, а не только конечный результат. Неверный порядок
открывает обход защиты — и тесты это видят.

**Статус: verified.**

## Процессная ошибка, которую стоит помнить

Для восстановления после фальсификации использовался `git checkout -- <файл>`.
Это откатило не только внедрённую поломку, но и **незакоммиченные правки
поверх закоммиченного файла** — правки `export_dir` в `export.py` и
`html_reader.py` и два докстринга пришлось делать заново. Правильный приём —
копия файла в scratch до мутации и восстановление из неё (так сделана
фальсификация 8b). Записано, чтобы не повторять.

## Security pass (изменение классифицировано CRITICAL)

Что новое позволяет недоверенному вводу? Единственное изменение поведения —
`unquote` над `href`, который приходит из экспорта, то есть из данных,
управляемых не нами. Вектор: percent-кодированный обход защиты от выхода
за корень экспорта.

Проверено (фальсификация A3.2 + независимо `boundary-guard`):
- `%2e%2e%2f` → `../` → `resolve()` схлопывает → `is_relative_to` = False → отбито
- `%2e%2e%5c` (windows-разделитель) → отбито
- `%2Fetc%2Fpasswd` → отбито
- двойное кодирование `%252e%252e%252f` → `unquote` одноразовый, остаётся
  литералом `%2e%2e%2f`, резолвится **внутри** `files/`, наружу не уходит

Санитизация текста исключений прав не расширяет — она их сужает
(меньше информации наружу). `[dev]`-extra в `pyproject.toml` рантайм не
трогает.
