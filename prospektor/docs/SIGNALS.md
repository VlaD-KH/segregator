# Каталог сигналов

Сигнал — результат одной пробы: чистой функции от загруженных страниц и известных
фактов. Ни одна проба не ходит в сеть сама, поэтому все они тестируются на замороженных
фикстурах и воспроизводимы: те же входные данные — тот же результат.

У каждого сигнала есть **evidence**: URL, время проверки и хэш куска HTML. Цифра в
досье прослеживается до сигнала, сигнал — до evidence. Без этого список лидов нельзя
нести клиенту.

Колонка «что предлагать» — не украшение: она и есть содержание разговора с владельцем.
Формулировки живут в `src/prospektor/export/dossier.py` (`REMEDIES`) и в поле `why`
профиля, меняются осознанно и проверяются глазами.

---

## Три состояния, а не два

Сигнал может отсутствовать — и это не то же самое, что «ложь». Прогон по
Старгарду поймал случай, когда сайт был заявлен, загрузка вернула 403, а модуль
записал «сайта нет»: сбой связи порождал лид на пустом месте.

Поэтому `web.has_site = false` выставляется только при **определённом**
отсутствии: адрес не заявлен вовсе, домен не резолвится, главная отвечает
404 или 410, либо адрес ведёт на чужую площадку. Таймаут, 403, обрыв соединения
и запрет в robots.txt дают `web.check_inconclusive` и `web.check_failed` с
причиной, а сам `web.has_site` **не выставляется** — правило скоринга его
пропустит.

Отсюда же колонка `coverage` в оценке: доля веса профиля, которая была измерена.
Разрыв 100 по двум правилам из девятнадцати и разрыв 100 по пятнадцати — разные
утверждения.

## A. `web.*` — присутствие в вебе

Отвечает на вопрос «есть ли вообще что аудировать».

| Сигнал | Что значит | Что предлагать |
|---|---|---|
| `web.has_site` | работающий **собственный** сайт | посадочная страница с меню, часами и кнопкой заказа |
| `web.declared_site` | адрес заявлен на карте | — |
| `web.only_social` | вместо сайта — Facebook/Instagram/Linktree | свой сайт: соцсеть не отдаёт разметку и владеет каналом |
| `web.site_reachable` | сайт ответил | — |
| `web.is_placeholder` | заглушка: «strona w budowie», парковка домена, дефолт хостинга | заменить на рабочий сайт |
| `web.https` | адрес по HTTPS | — |
| `web.cms` | движок: WordPress, Wix, Shoper, UpMenu, самопис | определяет, кто чинит: владелец или разработчик |
| `web.copyright_year` | год в подвале | «сайт брошен в 2019» — аргумент в разговоре |
| `web.mobile_viewport` | есть `meta viewport` | мобильная вёрстка: больше половины заказов с телефона |
| `web.text_len` | объём видимого текста | — |
| `web.check_inconclusive` | сайт заявлен, но проверить не удалось | сигнал `has_site` не выставляется вовсе |
| `web.check_failed` | причина: `dns`, `not_found`, `timeout`, `connect`, `tls`, `http_error`, `robots` | — |
| `web.url_kind` | что за адрес: `own`, `booking`, `delivery`, `social`, `directory`, `marketplace`, `maps_link`, `none` | считается без загрузки |
| `web.url_platform` | имя площадки: `booksy`, `pyszne`, `facebook`… | — |
| `web.platform_profile_only` | всё присутствие — профиль на чужой площадке | своя страница рядом с профилем |

`web.has_site` намеренно **не** засчитывает страницу в соцсети: там нет ни разметки,
ни меню, ни приёма заказов, и владелец не управляет тем, что о нём прочитает агент.

## B. `seo.*` — качество и согласованность

| Сигнал | Что значит |
|---|---|
| `seo.title_present`, `seo.title_len`, `seo.title_ok` | title есть и укладывается в 10–65 символов |
| `seo.description_len`, `seo.description_ok` | description в диапазоне 50–170 |
| `seo.h1_count`, `seo.h1_ok` | ровно один `h1` |
| `seo.canonical` | объявлен канонический адрес |
| `seo.og_tags` | есть Open Graph |
| `seo.lang_declared` | объявлен язык страницы |
| `seo.indexable` | нет `noindex` и нет глухого `Disallow: /` |
| `seo.sitemap_declared` | в robots.txt указан sitemap |
| `seo.nap_phone_match` | телефон с карты встречается на сайте |
| `seo.nap_city_match` | город с карты встречается на сайте |
| `seo.psi_performance`, `seo.psi_seo`, `seo.psi_accessibility` | оценки PageSpeed Insights (нужен ключ) |

**NAP** (Name–Address–Phone) — самая недооценённая позиция списка. Расхождение между
сайтом, картой и реестром снижает локальные позиции и путает ассистента, а чинится за час.

## C. `aio.*` — читаемость для ИИ-агентов

Ядро модуля. Логика выведена из того, как агент реально принимает решение: он не
«смотрит на сайт», а вызывает инструменты и читает структурированные данные.

| Сигнал | Что значит | Почему это стоит денег |
|---|---|---|
| `aio.jsonld_present` | есть блоки JSON-LD | без них агенту нечего процитировать |
| `aio.jsonld_broken` | блок есть, но не парсится | самая дешёвая правка из всего списка |
| `aio.jsonld_types` | найденные типы Schema.org | — |
| `aio.localbusiness_schema` | есть `LocalBusiness`/`Restaurant`/`Organization` | базовая видимость для ассистента |
| `aio.menu_machine_readable` | меню размечено `Menu`/`MenuItem` | запрос «острое, без глютена, до 50 zł» фильтрует только по разметке |
| `aio.menu_items_count` | сколько позиций в разметке | — |
| `aio.menu_is_image_only` | меню выложено картинкой или PDF | состав и цены не читает ни поиск, ни агент |
| `aio.price_in_markup` | цены машиночитаемы | без них заведение выпадает из фильтра по бюджету |
| `aio.diet_tags` | есть `suitableForDiet`, аллергены | фильтр «без глютена» отсекает заведения без тегов |
| `aio.alt_names` | у позиций есть синонимы (`alternateName`) | «рамен» и «японский суп с лапшой» — разные запросы |
| `aio.opening_hours_schema` | часы работы в разметке | «открыто сейчас» проверяется по ней |
| `aio.geo_schema` | адрес и координаты в разметке | — |
| `aio.ai_crawlers` | по каждому роботу: допущен или нет | — |
| `aio.ai_crawlers_allowed` | ни один ИИ-робот не закрыт | закрытый GPTBot = отсутствие в ответах ассистентов |
| `aio.ai_crawlers_blocked` | список закрытых | — |
| `aio.llms_txt` | есть `/llms.txt` | — |
| `aio.js_dependent` | контент появляется только после JS | робот без выполнения скриптов видит пустую страницу |
| `aio.raw_text_ratio` | доля текста в исходном HTML к отрендеренному | порог `js_dependent` — треть |

Проверяемые роботы: `GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`,
`anthropic-ai`, `PerplexityBot`, `Google-Extended`, `CCBot`, `Applebot-Extended`.
Явное правило для конкретного бота приоритетнее общего `User-agent: *` — так же,
как это трактуют сами роботы.

`aio.menu_is_image_only` сознательно осторожен: он не выставляется, если машиночитаемое
меню найдено. Лучше пропустить случай, чем обвинить заведение в том, чего нет.

## D. `ops.*` — приём заказов и общение

Самый коммерчески понятный разрыв. Три состояния, между которыми идёт разговор:

1. **заказов онлайн нет вообще** — `ops.phone_only`;
2. **есть, но только через агрегатор** — `ops.aggregator_only`, оборот идёт мимо кассы с комиссией;
3. **есть свой канал** — `ops.own_order_channel`, чинить нечего, это не лид.

| Сигнал | Что значит |
|---|---|
| `ops.aggregators` | найденные агрегаторы: Pyszne.pl, Glovo, Wolt, Uber Eats, Bolt Food |
| `ops.order_widgets` | свой движок заказа: UpMenu, Restaumatic, Skubacz, GoMobi, Papu |
| `ops.online_order` | заказ возможен хоть как-нибудь |
| `ops.own_order_channel` | есть собственный канал |
| `ops.aggregator_only` | только агрегатор |
| `ops.reservation_widgets`, `ops.reservation` | онлайн-запись: Booksy, Moment, Versum, OpenTable, resmio |
| `ops.booking_platform` | площадка записи, найденная по адресу карточки — известна до аудита |
| `ops.booking_platform_only` | запись есть, но целиком на чужой площадке |
| `ops.delivery_platform` | агрегатор доставки, найденный по адресу карточки |
| `ops.chat_widgets`, `ops.chat` | Messenger, WhatsApp, Tawk, Smartsupp, Crisp, LiveChat, Tidio |
| `ops.contact_form`, `ops.email_reachable` | форма и почта |
| `ops.phone_only` | телефон есть, других каналов нет |
| `ops.map_delivery`, `ops.map_takeaway`, `ops.map_reservation` | владелец сам отметил на карте — значит спрос есть |
| `ops.opening_hours_known` | часы работы известны |

## E. `rep.*` — репутация как прокси спроса

| Сигнал | Что значит |
|---|---|
| `rep.rating` | рейтинг |
| `rep.reviews_count` | число отзывов |
| `rep.has_traction` | отзывов не меньше десяти — ниже выборка не значит ничего |
| `rep.contactable` | есть телефон, почта или сайт |

Группа скромная: без платного источника отзывов доступны только рейтинг и количество.
Но именно они отвечают на вопрос, который важнее всех поломок — **есть ли спрос**.

## F. `reg.*` — реестры (польский пакет, планируется)

`reg.active`, `reg.pkd_primary`, `reg.legal_form`, `reg.vat_status`, `reg.age_years` —
из CEIDG, KRS и белого списка НДС. Адаптеры описаны в `docs/SOURCES.md`.

|---|---|
| `audit.completed_at` | стадия audit по карточке прошла. Нужен потому, что часть сигналов пишется раньше, на enrich: «есть сигналы» больше не означает «проверено» |

## Как добавить сигнал

1. Фикстура в `tests/fixtures/sites/` — реальная страница, на которой дефект виден.
2. Проба в нужном модуле `src/prospektor/probes/` — чистая функция, без сети.
3. Тест в `tests/probes/` — и на срабатывание, и на **отсутствие ложного срабатывания**.
4. Правило с весом, `title` и `why` в `profiles/*.yaml`. Текст живёт в профиле,
   потому что один и тот же сигнал означает разное в разных вертикалях: «только
   площадка» у ресторана — это комиссия с заказа, у салона — абонплата за место.
5. Запасная формулировка в `REMEDIES` (`src/prospektor/export/dossier.py`), если
   сигнал встречается больше чем в одной вертикали.

Порядок именно такой: сначала фикстура и тест, потом код. То же правило, что в основном
проекте — «прежде чем менять правило классификации, добавь фикстуру и тест на неё».
