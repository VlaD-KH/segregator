# Прогон: Щецин, 2026-09-07

Калибровочный город. Старгард (65 тыс.) остался контрольной точкой — он вскрыл
дефекты, описанные в `RUN-STARGARD.md`; Щецин (около 390 тыс.) даёт выборку на
порядок больше и проверяет, обобщаются ли выводы.

Обобщаются. Доля мусора выросла с 13% до 19%, соотношение вертикалей сохранилось,
а вертикаль красоты подтвердилась как крупнейшая.

## Выборка

16 823 POI в bbox 53.32–53.53 N, 14.40–14.80 E. Стоимость: **31 МБ и 35 секунд**
HTTP range-запросами, один файл из шестнадцати, две row group из 256.
После дедупликации — 16 446 карточек (склеено 377).

Аудит в этой среде по-прежнему невозможен: egress-политика закрывает сайты
бизнесов. Всё ниже получено из одного лишь discover.

**213 салонов, у которых всё веб-присутствие — поддомен на Booksy, видны сразу

раньше такой адрес считался «сайт есть» и уходил в аудит как чужая страница.

| Причина | Сколько |
|---|---|
| вне выбранных категорий | 11 398 |
| нелидовая категория (поштоматы, банкоматы, школы, костёлы) | 2 330 |

Доля структурного мусора — 3 253 из 16 446, то есть **19%**. В Старгарде было 13%:
в большом городе больше банкоматов, поштоматов и сетевых точек на единицу
живого бизнеса.

## Что подтвердилось и что изменилось в коде

Прогон подтвердил все шесть дефектов, найденных на Старгарде, и вскрыл ещё три,
которые видны только на масштабе:

**Склейка была квадратичной.** Каждая новая запись сравнивалась со всей базой.
На двух тысячах POI это незаметно, на шестнадцати — четверть миллиарда сравнений
и прогон, который не заканчивается. Добавлен пространственный индекс по ячейкам
0.003° с проверкой девяти соседних: 40 секунд на весь город.

**Классификация адреса ломала отбор кандидатов.** После M2.2 сигналы стали
писаться уже на стадии enrich, и правило «пропускать уже проверенные» сочло
проверенными все 16 446 карточек — кандидатов осталось ноль. Введён явный маркер
`audit.completed_at`, который выставляет только стадия audit.

**Скоринг оценивал весь город по правилам одной вертикали.** Фотограф в Грыфино
получал разрыв 100 по правилам красоты. Профиль теперь линза: `score` считает
только свою вертикаль, 1 840 карточек вместо 16 446.

Дополнительно: адаптер OSM вообще не записывал категорию, поэтому карточка,
найденная только в OSM, выпадала из любого профильного скоринга.

## Покрытие: почему «разрыв 100» здесь предварительный

Появилась колонка `coverage` — доля веса профиля, которая реально измерена.
Сейчас она равна **0.102**: без аудита проверяется только то, что видно из
адреса, то есть два правила из девятнадцати.

Это сознательно вынесено в выдачу, а не спрятано. Разрыв 100 по двум правилам и
разрыв 100 по пятнадцати — разные утверждения, и без этого числа они выглядели
бы одинаково.

## Склейка независимых заведений: измерено, но не проверено

Появилась команда `prospektor doctor`, которая делает эту неопределённость
проверяемой. По Щецину:

| | |
|---|---|
| Карточек всего | 16 446 |
| Собранных из записей с разными адресами | 246 (1.5%) |
| Из них адреса на **одной** улице | 135 |
| Из них адреса на **разных** улицах | **111 (0.7%)** |

Разделение оказалось содержательным. «USKIN» на al. Wojska Polskiego 11/4,
13A/2, 13a/U6 и 16 — это одно заведение, записанное четырьмя разными способами,
и склейка верна. А «Blast Tattoo Studio» собрал пять улиц: Bałuki 5,
Jagiellońska 1, Kaszubska 3/2, plac Lotników 7/3. Тут либо студия переезжала и
Overture помнит старые адреса, либо это разные бизнесы-тёзки.

Автоматически отличить одно от другого нельзя, поэтому список выносится
человеку отсортированным: `doctor --strict` показывает только случаи с разными
улицами. Проверка этих 111 карточек глазами — работа, которую я не делал.
