## [Unreleased]

### Добавлено

- **Читатель HTML-экспорта Telegram Desktop** (`src/segregator/ingest/html_reader.py`).
  Реальный экспорт канала «бухгалтерия» сделан в HTML (`messages.html` +
  пагинация), а не в `result.json`. Парсер на `beautifulsoup4` отдаёт те же
  `RawMessage` / `RawAttachment`, что и JSON-читатель.
- **Слой выбора формата экспорта** (`src/segregator/ingest/export.py`).
  `result.json` есть → JSON-читатель; иначе `messages*.html` в корне →
  HTML-читатель; иначе `FileNotFoundError` с упоминанием обоих форматов.
  `normalize.py` про формат источника больше не знает.
- **Разведчик структуры HTML** (`probe/02_html_structure.py`) — обезличенный
  отчёт (текст → длина, путь → каталог+расширение, дата → маска).
- **`docs/FUNCTIONAL_CHECKLIST.md`** — карта функционала Э1–Э7 с индексом
  отказов «симптом → вероятная причина» и списком дефектов D1–D21,
  найденных разбором кода и ревью до первого реального прогона.
- Зависимость `beautifulsoup4>=4.12` (бэкенд `html.parser`, без `lxml`).
- `[project.optional-dependencies] dev = ["pytest>=9.0"]` — `pip install -e ".[dev]"`
  собирает тестовое окружение на свежем клоне одной командой.

### Исправлено

- **Percent-encoded имена вложений больше не теряются** (дефект D1).
  `href` в HTML-экспорте процентно-кодирован; без декодирования путь с
  литеральным `%20` не находил файл, и вложение **тихо** уходило в счётчик
  «не найдено». На польских именах с пробелами и диакритикой это дало бы
  десятки ложных пропусков, неотличимых от невыгруженного медиа.
  Порядок: decode → resolve → проверка выхода за корень (обратный порядок
  открывал бы обход защиты; закреплено тестом).
- **Текст исключений больше не выносит данные экспорта** (дефект D2).
  Убраны: сырая строка даты, имя файла вложения (в обоих читателях), полный
  путь к документу, а также корень `EXPORT_DIR` — вместо него называется ключ
  конфига. Исключения из конвейера уходят в stderr и в вывод CLI, то есть
  ровно в тот канал, который копируют в переписку при отладке
  (`docs/DATA_BOUNDARY.md`, инвариант 4). Инвариант держится тестом на
  `ast`-разборе всех `raise` в `ingest`/`extract`/`classify`/`route`/`serve` —
  он ловит f-строку, конкатенацию, `.format()`, `%`-формат и `from`-цепочку.
