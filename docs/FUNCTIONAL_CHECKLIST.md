# Карта функционала и индекс отказов

**Это не план написания тестов.** Это список того, что в системе должно
существовать и работать правильно, плюс — для каждого пункта — как выглядит
поломка снаружи и где её наиболее вероятная причина.

Порядок работы с документом:

1. Функционал реализуется. Тесты заранее по этому списку **не пишутся**.
2. Проверка идёт фактическим прогоном: CLI руками, а с Э6 — ИИ-агентом,
   который гоняет Telegram-бота как пользователь и смотрит на экран.
3. Прогон что-то сломал → ищешь **симптом** в индексе → получаешь список
   вероятных причин, отсортированный по правдоподобию → проверяешь их
   по порядку.
4. Причина найдена → **тогда** пишется тест, фиксирующий именно её, чтобы
   не вернулась. Тест — след от бага, а не ритуал.

Колонка «чем закрыт» честная: `—` значит ничем, `pytest` значит есть
автотест, `рука` значит проверяется только глазами на прогоне.

Легенда статуса: **✓** работает · **◐** реализовано, но не проверено на
реальных данных · **✗** известно, что сломано или отсутствует · **○** ещё
не реализовано (этап не начат).
