# Segregator — контекст проекта для Claude Code

Автономная бухгалтерская ИИ-система для Польши (JDG и Sp. z o.o.).
Первый работающий кусок — разбор Telegram-канала «бухгалтерия» в архив.

## Правило номер один: контур данных

Документы и всё, что из них извлечено, **не покидают эту машину**.

| Плоскость | Что там работает | Что видит |
|---|---|---|
| **L — Local runtime** | Четвёрка доменных агентов на локальной LLM + Python-калькуляторы | Реальные фактуры, PIT-11, ZUS, PESEL, суммы |
| **C — Claude Code** | Субагенты разработки (`.claude/agents/`) | Только код, правила, схемы, синтетические фикстуры, обезличенные счётчики |

Claude Code **никогда** не читает `C:\Users\Huawei\Downloads\Telegram Desktop\JDG`,
`archiwum/`, `blobs/`, `*.db`, `logs/`. Запреты продублированы в `.claude/settings.json`.
Если для отладки нужен пример документа — берётся синтетическая фикстура из
`tests/fixtures/`, а не настоящая бумага.

## Железо (замерено)

- CPU: AMD Ryzen 5 3500U, Vega iGPU. **NVIDIA нет → vLLM не используем.**
- LLM: llama.cpp / Ollama, GGUF Q4_K_M, класс модели 4B.
- Следствие: локальная модель — дорогой ресурс. Каскад устроен так, чтобы
  до неё доходили единицы процентов документов. Тяжёлые прогоны — ночью, в BATCH.
- Диск C: свободно ~19 ГБ из 238 — следить.

## Разделение труда: код считает, модель объясняет

Налоги, ZUS, VAT и амортизацию считает **детерминированный Python**, покрытый
тестами. Модель 4B не считает деньги — она классифицирует, извлекает поля и
формулирует объяснение. Любая цифра в выдаче агента должна быть прослеживаема
до вызова калькулятора или до поля документа.

## Юридическая граница

Система готовит документы и расчёты **для бухгалтера**, а не вместо него.
Ни один агент не подаёт декларацию, не отправляет фактуру в KSeF и не платит
взносы. Агент готовит файл — отправляет человек. Agent-Doradca показывает
варианты и допущения, но не говорит «сделай так».

## Регуляторный контекст (проверено 2026-08-31)

- KSeF обязателен: с 2026-02-01 для крупных, **с 2026-04-01 для остальных**,
  включая JDG. Приём фактур через KSeF обязателен для всех с 2026-02-01.
- Структура: **FA(3)**. API: **KSeF 2.0** (документация опубликована 2025-06-30,
  тестовая среда с 2025-09-30).
- Переходный лимит 10 000 zł/мес на фактуры вне KSeF — до 2026-12-31.
  С 2027-01-01 полный санкционный режим.
- **Следствие для архитектуры:** для документов 2026+ KSeF — основной канал,
  XML вместо OCR. OCR остаётся для чеков, зарубежных фактур и для архива 2025,
  который в KSeF не попадал.

## Структура репозитория

```
agents/            спецификации доменных агентов (плоскость L), YAML + промпты + JSON-схемы
src/segregator/    пайплайн: ingest → extract → classify → route → serve
rules/             rules.yaml и тесты правил
schemas/           JSON-схемы контрактов между агентами
tests/fixtures/    ТОЛЬКО синтетические документы
probe/             локальные скрипты разведки (выхлоп не покидает машину)
docs/              архитектура, контур данных
.claude/           агенты и настройки Claude Code (плоскость C)
```

## Как со мной работать

- Язык общения — русский. Имена папок, категорий и колонок реестра — польские.
- Системные промпты доменных агентов — на английском (модель 4B на нём стабильнее),
  доменные термины и enum-значения — польские.
- Прежде чем менять правило классификации, добавь фикстуру и тест на неё.
- Прежде чем добавить сетевой вызов, объясни в PR, почему он не нарушает контур.
